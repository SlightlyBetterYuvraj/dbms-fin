# Implementation Decisions / Agent Additions

This file records technical decisions and agent-made choices for the University Timetable & Class Management System prototype, as required by `AGENTS.md` and `docs/10_OPEN_ITEMS_AND_ASSUMPTIONS.md`.

| ID | Date/phase | Decision or addition | Why necessary | Alternatives considered | Impact/risk | Reversible? | Requires user approval before production? |
|---|---|---|---|---|---|---|---|
| DEC-01 | 2026-10-13 / Phase 0 | Node.js v22 + TypeScript application server (Express) | AI Studio Build mode runtime supports Node.js web apps; TypeScript provides strict static typing for scheduling invariants and API contracts. | Fastify, Next.js API routes | Low risk; portable and standard for AI Studio environment. | Yes | No |
| DEC-02 | 2026-10-13 / Phase 0 | Dual-compatible database architecture: PostgreSQL/Supabase schema + zero-cost local transactional SQLite/in-memory engine for deterministic testing | Allows ₹0 cost offline testing of atomic transactions, concurrency races, and rollbacks without needing external cloud credentials or paid plans. | PostgreSQL-only (requires active cloud connection or local docker daemon) | Zero cloud cost; high test reliability. | Yes | Yes (confirm Supabase project configuration before production deployment) |
| DEC-03 | 2026-10-13 / Phase 0 | Isolated Python 3.12 + OR-Tools solver under `generator/` with versioned JSON package I/O contract | AI Studio Node runtime cannot execute Python within its process. Python 3.12 has verified OR-Tools 9.15 on the machine. | In-process JS solver (cannot match OR-Tools CP-SAT capabilities) | Clean architectural decoupling; runs locally and behind hosted service without modifying core API. | Yes | No |
| DEC-04 | 2026-10-13 / Phase 0 | Configurable default timetable grid: Mon–Fri, 8 1-hour periods (09:00–17:00), lunch break at period 4 | Exact university calendar is unresolved in spec. Configurable grid allows testing full multi-semester scheduling. | Hardcoded slots | Flexible; easily configured by admin without code changes. | Yes | Yes (university must approve official period timings) |
| DEC-05 | 2026-10-13 / Phase 0 | Strict rejection of odd practical hours (`ERR_ODD_P_HOURS`) | D07/D44 explicitly prohibits inventing conversion or rounding rules for odd practical contact hours. | Rounding down or up | Correctly surfaces unconfigured courses for admin attention. | Yes | Yes |
| DEC-06 | 2026-10-13 / Phase 0 | Transactional outbox event pattern with in-memory / persisted queue for post-commit notifications | Ensures notifications are only dispatched after successful commit and prevents duplicate sends on retries. | Synchronous notification inside transaction (risks partial failures or external side-effects before commit) | Guarantees notification consistency; durable. | Yes | No |
| DEC-07 | 2026-10-13 / Phase 0 | Upload limits: 5MB max payload, 10,000 max rows | Security and memory stability safeguard against unbounded file processing. | Unbounded uploads | Prevents DoS on free-tier compute limits. | Yes | No |
| DEC-08 | 2026-10-13 / Phase 0 | Minimal React + TypeScript single-page client interface | Phase 7 requirement for minimal UI to exercise all real workflows (student, teacher, admin) without decorative distraction. | Server-rendered HTML templates | Directly satisfies user prompt requirement for minimal workflow UI. | Yes | No |
